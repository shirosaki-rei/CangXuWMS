## 7. AI 四项（5 min）

### 7.1 库位推荐 X02

入库详情 → 右上「AI 选位」。要说清三件事：
- 输出是**主推 1 + 备选 2**，每条带一句人话理由（同物料集中、剩余容量、距离）
- 置信度按 Top1−Top2 **分差**（高 ≥8 / 中 3–8 / 低 <3）；**低置信度不给主推**，只列 3 个并列
- 硬约束优先：危品库位、超容量、锁定库位**直接淘汰**，不进备选

点「不再提示 7 天」→ 静默生效（BR-021）。

### 7.2 提交前校验 X04

第 3.6 / 4.4 步已经展示过。补一句规则表结构：
`(单据类型, 规则号) → 函数`，共 11 条；不适用的显式返回 SKIP，所以入库单会看到「R5 不适用」。

**阻断态**：出库可用库存不足时，`submittable=false`，对话框提交按钮置灰（BR-017），后端也会拒绝并回传 `blocking_rules`。

### 7.3 智能问数 X01

AI 建议层 → 智能问数，点示例问题或手输：

| 问题 | 预期 |
|---|---|
| 上周 A3288 出了多少台？ | 结论 + 按日表格 + **口径说明** + 可展开 SQL |
| 哪些物料低库存 | 低库存物料列表 |
| 今天天气怎么样 | **「该口径暂无数据，已记录待补充模板」**，不编 SQL |

**要强调的设计**：SQL 来自预置模板，LLM 不参与生成（默认根本没接）。所以同一个问题永远同一条 SQL、同一份结果。

## 11. 常见追问

**Q：库存会不会算错？**
A：库存只能通过 `domain/stock.py` 改，那里用 `SELECT … FOR UPDATE` 行锁 + 按 `inventory.id` 升序加锁防死锁；所有变动都写 `txn` 流水，每日对账会比对「库存 = 流水累计」，不一致会落 `reconcile_diff` 并告警。

**Q：AI 会不会瞎编？**
A：三类建议（库位/路径/校验）都是本地规则算的，不依赖大模型；问数只认预置指标模板，LLM 默认不接、也不允许生成 SQL。没命中模板就直接说「暂无数据」。

**Q：AI 能不能改数据？**
A：物理上不能。AI 用的是独立的只读数据库账号（只授 SELECT），代码层有 boundary 检查禁止 AI 目录 import 写会话，运行时 AI 路由拿不到写 session。

**Q：断网怎么办？**
A：APP 扫码先写本地 SQLite 队列，恢复网络后按扫码时间顺序补传；服务端用客户端生成的 `client_op_id` 去重，重放不会重复记账。

**Q：能上几个人同时用？**
A：架构按 200 并发设计（单机 16G/4C，uvicorn 3 worker）。**吞吐与 P95 尚未压测**，上线前应在目标环境跑一轮。

**Q：数据怎么备份？**
A：每日 03:00 全量 `mysqldump` → gzip，保留 7 天；另有手工脚本 `tools/backup.sh`。**恢复演练还没在目标环境实跑过**，这是上线前必做项。
